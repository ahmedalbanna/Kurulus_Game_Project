# 🎮 Kurulus In-Game HUD — Architecture & Feature Breakdown Plan

## Executive Summary

This plan designs the ECS architecture for the complete in-game HUD: the Top Resource Bar, Minimap Panel, Command Bar, Selection Panel, Hero Bar, Notification Stack, and Objectives Panel. It builds on the existing `UILogicPlugin` pattern (marker components + render systems in `Update` + logic systems in `FixedUpdate`) and integrates with the existing ~40 event types and game state system.

## 2. Architecture Pattern (Established Convention)

Every UI element follows this exact pattern:

```
┌─────────────────────────────────────────────────────┐
│ 1. Marker Component (kurulus-core)                   │
│    #[derive(Component)] struct FooBarRoot;           │
│                                                      │
│ 2. Resource (kurulus-core, if state needed)          │
│    #[derive(Resource)] struct FooBarState { ... }    │
│                                                      │
│ 3. Logic System (FixedUpdate schedule)               │
│    fn foo_logic_system(..., ResMut<FooBarState>)     │
│    → Reads events, mutates state resource            │
│                                                      │
│ 4. Render System (Update schedule)                   │
│    fn foo_render_system(..., Query<Entity, With<FooBarRoot>>>) │
│    → Spawns/updates/despawns Bevy UI entities        │
│                                                      │
│ 5. Tests in same module                              │
│    #[cfg(test)] mod tests { ... }                    │
└─────────────────────────────────────────────────────┘
```

**Key rules:**

- Render systems use `Commands` to spawn/update/despawn — never direct world mutation
- Marker components enable O(1) entity lookup each frame
- Logic runs in `FixedUpdate` (deterministic), rendering in `Update` (visual)
- All UI entities use `PositionType::Absolute` for precise placement
- Headless mode: entities spawn but are invisible (no `UiPlugin`)

## 4. System Designs

### 4.1 Top Resource Bar

**File:** `kurulus-systems/src/ui/top_bar.rs`

**Logic System (`FixedUpdate`):**

```
fn top_bar_logic_system(
    resources: Res<ResourceStockpile>,
    city: Res<CityState>,
    game_time: Res<GameTime>,
    mut bar_state: ResMut<ResourceBarState>,
)
```

- Reads `ResourceStockpile` (gold, wood, food, iron) and `CityState` (population)
- Reads `GameTime` for the clock display
- Computes deltas by comparing current frame to previous frame (store `previous_*` fields)
- Updates `ResourceBarState` each tick

**Render System (`Update`):**

```
fn top_bar_render_system(
    bar_state: Res<ResourceBarState>,
    mut commands: Commands,
    root_query: Query<Entity, With<TopBarRoot>>,
)
```

- Spawns a horizontal `Node` at the top of the screen (`position_type: Absolute, top: 0, left/right: stretch`)
- Child nodes for each resource: icon + text + delta arrow
- Color coding: normal (white), low (<10% → orange), empty (0 → red with warning)
- Population shown as "current/max" fraction
- SP shown as clickable counter
- Time shown as "HH:MM" format
- Speed control: three small buttons (1×, 2×, 3×) that mutate a `GameSpeed` resource

**Layout:**

```
┌─────────────────────────────────────────────────────────────┐
│ 🪵 250(+3)  ⛏️ 120(-1)  🌾 180  💰 45  👑 8  ⏰ 14:30  ▶▶ │
└─────────────────────────────────────────────────────────────┘
```

### 4.6 Notification Stack

**File:** `kurulus-systems/src/ui/notifications.rs`

**Logic System (`FixedUpdate`):**

```
fn notification_dispatch_system(
    damage_events: EventReader<DamageDealt>,
    death_events: EventReader<UnitDied>,
    objective_events: EventReader<ObjectiveCompleted>,
    mission_events: EventReader<MissionEnded>,
    mut notifications: ResMut<NotificationStack>,

- Reads combat events → generates warning notifications ("Archer under attack!")

- Ticks down durations, removes expired entries

**Render System (`Update`):**

```

- Spawns a vertical stack in the center-left area
- Each notification: colored background + icon + text + fade-out animation
- Priority determines max visible count (High=3, Medium=2, Low=1)
- Fade-out: alpha decreases over last 1 second of duration
- Color by type: Warning=orange, Error=red, Success=green, Info=blue, Achievement=gold

### 4.8 Selection Processing System (TODO → Implementation)

**File:** `kurulus-systems/src/ui/mod.rs` (replace TODO stub)

```
fn selection_processing_system(
    mut select_events: EventReader<SelectEvent>,
    mut box_select_events: EventReader<BoxSelectEvent>,
    mut control_group_events: EventReader<ControlGroupEvent>,
    mut selection_changed: EventWriter<SelectionChanged>,
    mut selection_state: ResMut<SelectionState>,
    mut control_groups: ResMut<ControlGroups>,
    selectables: Query<Entity, With<Selectable>>,
)
```

**Logic:**

1. `SelectEvent` → If `entity` is `Some`, select that entity (replace or add based on shift). If `None`, deselect all.
2. `BoxSelectEvent` → Replace/add all entities in the box to selection.
3. `ControlGroupEvent` →
    - `Create`: Store current selection into `control_groups.groups[group]`
    - `Recall`: Replace selection with group's entities
    - `Append`: Add group's entities to current selection
4. After processing, emit `SelectionChanged` with `selected` and `previous` lists.
5. Update `SelectionState.selected`.

## 9. Risk Areas & Mitigations

|Risk|Mitigation|
|---|---|
|**Performance**: Minimap texture update every frame|Update minimap texture every 0.25s (4×/sec), not every frame. Cache the `Image` handle.|
|**Headless test compatibility**: UI render systems need `UiPlugin`|All render systems are harmless without `UiPlugin` — entities spawn but are invisible. Logic systems work independently.|
|**Selection state consistency**: Multiple input events per frame|Process all selection events in a single system, accumulate changes, emit one `SelectionChanged` at the end.|
|**Notification spam**: Too many events flooding the stack|Priority-based filtering + max visible count (3 high, 2 medium, 1 low) + deduplication (same message within 2s).|
|**Hero bar data availability**: Heroes may not exist in early game|`HeroBarState.heroes` is empty vec when no heroes → hero bar renders nothing or shows "No heroes available" placeholder.|
|**Minimap click coordinate mapping**: Screen ↔ world conversion|Use camera transform + viewport size to convert minimap pixel coords to world coords. Test with known positions.|

**Key design decisions:**

- Follows the exact existing pattern: marker component → logic system (FixedUpdate) → render system (Update) → tests
- All data flows through `Resource` types, never direct entity queries in render systems
- Minimap uses cached texture updated 4×/sec, not every frame
- Notification stack has priority filtering to prevent spam
- Selection processing accumulates all input events per frame, emits one `SelectionChanged`
- Everything is headless-test compatible (logic works without `UiPlugin`)

**4 implementation phases** spanning foundation → core HUD → advanced HUD → polish, with 8-12 tests per module.
