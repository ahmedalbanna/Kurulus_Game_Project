# Update Pipeline — Subsystem Update Order & Responsibilities

> **Description:** Detailed breakdown of each subsystem's update phase within a single simulation tick. Defines what each system does, its dependencies, and its performance characteristics.

---

## 1. Pipeline Phase Reference

Each simulation tick is divided into sequential phases. Phases are **strictly ordered** — no phase starts until the previous one completes.

```
PHASE 0:  PRE_TICK         — Global pre-tick bookkeeping
PHASE 1:  INPUT            — Player command processing
PHASE 2:  TRIGGERS         — Condition evaluation
PHASE 3:  AI               — Faction + entity AI
PHASE 4:  MOVEMENT         — Pathfinding + physics
PHASE 5:  STEALTH          — Detection + ambush
PHASE 6:  COMBAT           — Damage + morale
PHASE 7:  ECONOMY          — Resources + production
PHASE 8:  OBJECTIVES       — Mission progress
PHASE 9:  EVENTS_DEFERRED  — Scheduled event dispatch
PHASE 10: EVENTS_IMMEDIATE — Event queue flush
PHASE 11: POST_TICK        — Cleanup + garbage collection
```

---

## 2. Phase Details

### Phase 0: PRE_TICK

| Aspect | Detail |
|--------|--------|
| **Purpose** | Prepare for the tick — reset transient state, advance timers |
| **Systems** | Timer Manager, World State, Entity Registry |
| **Dependencies** | None (always runs first) |
| **Budget** | < 0.1 ms |
| **Operations** | |
| | • Increment global tick counter |
| | • Advance game clock by fixed_dt |
| | • Clear transient per-tick flags (e.g., `was_damaged_this_tick`) |
| | • Update all entity state timers (status effect durations, cooldowns) |

### Phase 1: INPUT

| Aspect | Detail |
|--------|--------|
| **Purpose** | Dequeue and process all player commands issued since last tick |
| **Systems** | Command Queue, Selection Manager |
| **Dependencies** | Pre_tick complete |
| **Budget** | < 0.2 ms |
| **Operations** | |
| | • Dequeue all pending commands |
| | • Validate commands (target exists, has authority) |
| | • Convert commands to entity orders |
| | • Assign orders to selected entities |
| | • Emit `Input_Command` events |

### Phase 2: TRIGGERS

| Aspect | Detail |
|--------|--------|
| **Purpose** | Evaluate all active trigger conditions |
| **Systems** | Trigger Engine |
| **Dependencies** | Input processed (triggers may depend on input events) |
| **Budget** | < 1.0 ms (assuming < 100 active triggers) |
| **Operations** | |
| | • Iterate active triggers |
| | • For polled triggers: evaluate conditions |
| | • For event-driven triggers: check if their event arrived this tick |
| | • If conditions met: execute trigger's action list |
| | • Mark one-shot triggers as disposed |
| | • Emit any events generated by trigger actions |

### Phase 3: AI

| Aspect | Detail |
|--------|--------|
| **Purpose** | Update all AI-controlled entities and faction-level AI |
| **Systems** | FactionAI, EntityAI, Threat Evaluator, Planning System |
| **Dependencies** | Triggers evaluated (AI reacts to trigger results) |
| **Budget** | < 2.5 ms |
| **Operations** | |
| | • **Faction AI (once per 10 ticks):** |
| |   • Evaluate global strategy |
| |   • Generate/update economic plan |
| |   • Generate/update military plan |
| | • **Entity AI (every tick):** |
| |   • Update state machine |
| |   • Evaluate threats in range |
| |   • Select targets |
| |   • Issue movement/attack orders |
| | • **Ambush AI:** |
| |   • Evaluate ambush opportunities |
| |   • Update stealth positioning |

### Phase 4: MOVEMENT

| Aspect | Detail |
|--------|--------|
| **Purpose** | Resolve entity movement, pathfinding, collision |
| **Systems** | Pathfinding, Movement Controller, Collision System |
| **Dependencies** | AI decided where entities should go |
| **Budget** | < 2.0 ms |
| **Operations** | |
| | • For entities with move orders: |
| |   • Request path from pathfinder |
| |   • Advance along path by (speed × fixed_dt) |
| | • Collision resolution: |
| |   • Push overlapping entities apart |
| |   • Formation cohesion (pull toward formation slot) |
| | • Update entity position + rotation |
| | • Update spatial hash (for queries) |
| | • Emit `Game_UnitMoved` (throttled) |
| | • Emit `Game_UnitEnteredZone` / `Game_UnitExitedZone` |

### Phase 5: STEALTH

| Aspect | Detail |
|--------|--------|
| **Purpose** | Update stealth zones, detection checks, ambush readiness |
| **Systems** | Stealth Manager, Detection System, Ambush Manager |
| **Dependencies** | New positions available from Movement |
| **Budget** | < 0.8 ms |
| **Operations** | |
| | • Update stealth zone membership for all units |
| | • For stealthed units: update detection levels |
| | • For detectors (sentries, scouts): scan for hidden units |
| | • Check ambush readiness conditions |
| | • Emit `Stealth_*` and `Ambush_*` events |

### Phase 6: COMBAT

| Aspect | Detail |
|--------|--------|
| **Purpose** | Process all combat actions — melee, ranged, siege, morale |
| **Systems** | Melee Combat, Ranged Combat, Siege System, Morale System, Status Effect Manager |
| **Dependencies** | Positions finalized, stealth resolved |
| **Budget** | < 3.0 ms (most expensive phase) |
| **Operations** | |
| | • **Melee:** For each engaged pair, calculate hit, apply damage |
| | • **Ranged:** For each ranged attacker, check range/line-of-sight, fire projectile |
| | • **Siege:** Apply siege damage to buildings |
| | • **Morale:** Update morale for all entities |
| | • **Status effects:** Apply tick effects (poison, regen) |
| | • **Friendly fire check:** Apply penalties |
| | • Emit `Combat_*` events |

### Phase 7: ECONOMY

| Aspect | Detail |
|--------|--------|
| **Purpose** | Process resource income, consumption, production queues |
| **Systems** | Economy Manager, Production System, Construction System |
| **Dependencies** | Combat may have killed units (affects income), buildings may have been destroyed |
| **Budget** | < 1.0 ms |
| **Operations** | |
| | • Calculate resource income from workers + buildings |
| | • Deduct food consumption (army upkeep) |
| | • Advance production queues (unit training, research) |
| | • Advance building construction progress |
| | • Check resource capacity limits |
| | • Emit `Game_ResourceChanged`, `Game_BuildingCompleted` |

### Phase 8: OBJECTIVES

| Aspect | Detail |
|--------|--------|
| **Purpose** | Evaluate mission objective states |
| **Systems** | Objective Manager, Mission Controller |
| **Dependencies** | Economy updated (objectives may check resource thresholds) |
| **Budget** | < 0.3 ms |
| **Operations** | |
| | • Check each active objective's completion conditions |
| | • Update objective progress values |
| | • If objective completed/failed: update state, emit events |
| | • Check victory/defeat conditions |
| | • Emit `Mission_*` events |

### Phase 9: EVENTS_DEFERRED

| Aspect | Detail |
|--------|--------|
| **Purpose** | Fire any scheduled/deferred events whose trigger time has arrived |
| **Systems** | Deferred Event Manager |
| **Dependencies** | All gameplay systems done (events may reference latest state) |
| **Budget** | < 0.2 ms |
| **Operations** | |
| | • Check priority queue for events due this tick |
| | • Pop due events, emit them through event bus |
| | • Recurring events: reschedule next occurrence |

### Phase 10: EVENTS_IMMEDIATE

| Aspect | Detail |
|--------|--------|
| **Purpose** | Flush the immediate event queue — dispatch all events generated this tick |
| **Systems** | Event Bus |
| **Dependencies** | All previous phases complete (all events for this tick have been emitted) |
| **Budget** | < 0.5 ms |
| **Operations** | |
| | • Process all events in the immediate queue |
| | • Dispatch to registered listeners in priority order |
| | • Handle consumption/cancellation |
| | • Log events (debug builds) |

### Phase 11: POST_TICK

| Aspect | Detail |
|--------|--------|
| **Purpose** | Cleanup, garbage collection, statistics |
| **Systems** | Entity Registry, Debug/Stats |
| **Dependencies** | All events dispatched |
| **Budget** | < 0.3 ms |
| **Operations** | |
| | • Remove entities marked as dead from active registry |
| | • Clear transient per-tick collections |
| | • Update statistics counters |
| | • Prepare dirty flags for UI sync |
| | • (Debug) check for leaked events or unprocessed commands |

## 3. Phase Dependency Graph

```
PRE_TICK (no deps)
   │
   ▼
INPUT (no deps)
   │
   ▼
TRIGGERS (dep: Input)
   │
   ▼
AI (dep: Triggers)
   │
   ▼
MOVEMENT (dep: AI)
   │
   ├──────► STEALTH (dep: Movement)
   │                │
   │                ▼
   │            COMBAT (dep: Stealth)
   │                │
   │                ▼
   └──────────► ECONOMY (dep: Combat)
                   │
                   ▼
              OBJECTIVES (dep: Economy)
                   │
                   ▼
              EVENTS_DEFERRED (dep: Objectives)
                   │
                   ▼
              EVENTS_IMMEDIATE (dep: Deferred)
                   │
                   ▼
              POST_TICK (dep: Events)
```

## 4. Parallelization Opportunities

| Phase Group | Can Run Parallel | Notes |
|-------------|-----------------|-------|
| AI (entity-level) | ✅ Yes | Each entity's AI is independent |
| Movement | ⚠️ Partial | Pathfinding per entity independent; collision resolution requires sync point |
| Combat | ⚠️ Partial | Per-pair combat independent; morale global effect requires sync |
| Economy | ❌ No | Global resource pools, sequential production queue |
